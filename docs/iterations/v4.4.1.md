# V4.4.1 迭代记录：GitHub Pages 自动部署

## 为什么增加公网部署

V4.4 的任务过程与官方影像已经完成，本轮不改页面内容，只补充稳定的公网访问入口，便于展览演示、验收和后续分享。

## GitHub Pages 工作方式

`.github/workflows/deploy-pages.yml` 在 `main` 分支收到 push 或手动触发时运行。工作流检出代码，使用 Node.js LTS 执行 `npm ci` 与 `npm run build`，将 `dist` 上传为 Pages artifact，再通过 `actions/deploy-pages` 发布。仓库权限、并发控制和 Pages 身份令牌已在 workflow 中声明。

## 最终网页地址

<https://happydailyly.github.io/China-Space-Museum/>

Vite 使用 `/China-Space-Museum/` 作为 base，以适配仓库子路径。

## 自动部署机制

以后向 `main` 推送提交会自动启动同一 workflow；也可以在 GitHub Actions 页面使用 `workflow_dispatch` 手动启动。部署过程不保存大型视频，网页内容和 V4.4 任务过程保持不变。

## 本轮范围与验证

本轮只新增 Vite Pages base、GitHub Actions workflow 和部署文档。`npm ci`、`npm run build` 的本地结果在发布前完成核验；Actions 与 Pages 的最终状态以 GitHub 远程检查为准。
