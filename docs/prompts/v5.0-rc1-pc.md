## 一、PC 终审范围

- 本轮只验收 PC 端。
- 浏览器视口固定为 `1600×900`，浏览器缩放 100%，截图使用 `fullPage: true` 的 PNG。
- 只生成首页和五座真实展厅共六张图：`01-home.png`、`02-launch.png`、`03-satellite.png`、`04-human.png`、`05-lunar.png`、`06-planetary.png`。
- 截图直接保存到 `docs/screenshots/v5.0-rc1-pc/`。
- 不生成手机端、平板端、`390×844`、`768px`、第二套 `1920×1080`，不建立 `mobile/`、`tablet/`、`1600/`、`1920/` 或其他截图子目录。
- 手机端和平板端结构本轮冻结；即使发现移动端问题，也只记录到 V5.1 TODO，不为 PC 终审修改响应式结构。

## 二、页面与展陈要求

### 首页

检查 Hero 是否有明确视觉重心、标题是否安全、字体是否合适；保留五条发展主线网络和真实展厅入口。关键时刻区分主要节点与辅助节点，共同技术底座不要再次读成五张等权卡片。主线入口需要支持鼠标和键盘操作。

### 进入太空

保持六枚火箭的连续尺度比较，真正让访客能比较高度、近地轨道运力和代表任务；参数可以通过轻交互展开，但不要让参数抢过火箭轮廓。长征五号继续作为大展品，媒体与来源保持清晰。

### 天基中国

保持卫星网络、导航、气象和遥感的不同观看关系，使三个问题成为清晰的视觉标题：我在哪里？天气正在发生什么？从太空能看清什么？

### 人在太空

强调人而不是航天器，清楚表达无人验证、有人进入太空、长期在轨工作三幕。说明为什么要先做无人验证，并确保神舟五号、交会对接、中国空间站三个展项形成纵向章节关系。

### 奔向月球

保留绕—落—回主路线，补充绕月捕获、动力下降、悬停避障、软着陆、采样起飞、月轨交会与返回等动作。月背支路继续解释中继通信、鹊桥和月背采样返回。

### 走向行星

保留地球到火星的概念距离、约七个月级旅程、通信时延和自主判断；解释行星持续运动、发射窗口和转移轨道，回答“为什么不是直线”。保持天问一号、祝融号和未来展项的不同展示方法。

## 三、来源、图片和视频

- 优先核验国家航天局、中国载人航天工程、中国气象局、北斗官网、中国科学院和 Wikimedia Commons 等可靠来源。
- 许可明确且允许本地使用时才加入本地素材；授权不清晰的图片只保留官方或来源外链。
- 不下载大型视频；官方视频继续使用 link-only 入口，普通界面显示“观看官方影像”。
- 图片说明使用“图片—简短图注—来源”的层级，作者长字符串、许可证 URL 和原始文件名进入来源详情，避免来源信息抢占主体。

## 四、自动验收脚本

先检查项目是否已有 Playwright、浏览器自动化脚本和可复用截图能力；已有能力直接复用，不重复安装。若需修正，使用轻量脚本 `scripts/capture-review-pages.mjs` 和 `npm.cmd run screenshots`。

脚本必须从 `grandHalls.json` 和 App 路由读取真实展厅 ID，不硬编码已删除的路由；截图前等待页面、字体、图片、React 渲染和动画稳定，并安全关闭浏览器及临时服务。

截图后必须检查：

- 六个文件全部存在且非空；
- 不是浏览器错误页，没有 Vite 错误覆盖层、同源 404、console error 或 pageerror；
- 没有 broken image，图片有 alt，链接有可访问名称；
- 没有 1600px 桌面横向溢出；
- 实际读取六张图，检查标题遮挡、图片比例、字号、留白、拥挤、对齐、卡片高度、来源层级、Hero 重心、五厅差异、英文普通 UI 和内容空间利用。

如果发现明显 PC 问题，可以自行修复一轮，覆盖重新生成同名六张图片；移动端问题不要修。
